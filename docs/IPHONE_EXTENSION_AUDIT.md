# Аудит: YTVD как бэкенд для iPhone

Исходная точка — коммит `27a5cbd` (YTVD 1.2.1), рабочее дерево чистое.
Движок проверен перед изменениями: `YTVD --fetch` на YouTube-ролике прошёл
полный цикл «видео → аудио → склейка», файл содержит обе дорожки.

## Существующая архитектура

| Что | Где и как |
|---|---|
| Язык, сборка | Swift 6.3, SwiftPM, режим языка Swift 5. Зависимостей нет |
| Структура | `YTVDCore` — вся логика и интерфейс (библиотека, покрыта тестами); `YTVD` — точка входа; `YTVDCoreTests` — 155 тестов |
| Точка входа | `Sources/YTVD/YTVDApp.swift`: `@main`, служебные режимы `--doctor`, `--analyze`, `--fetch`, `--render`, иначе меню-бар-приложение |
| Движок | `MediaService` — обёртка над yt-dlp: `fetchInfo(url:)` и `download(plan:url:directory:baseName:onEvent:)`, отмена через `cancel()` |
| Процессы | `ProcessRunner` — `Process` + построчный разбор stdout/stderr, ожидание обоих потоков и завершения |
| yt-dlp | Ищется `BinaryLocator`: Application Support (обновления) → бандл → Homebrew/MacPorts/`~/.local/bin`. Путь к Deno передаётся `--js-runtimes`, к ffmpeg — `--ffmpeg-location`: приложение из Finder получает урезанный PATH |
| FFmpeg | Встроен в бандл (статическая сборка 8.1, arm64). Склейку делает yt-dlp (`--merge-output-format mp4`, `--remux-video mp4`) — без перекодирования. В сборке есть `hevc_videotoolbox` и `h264_videotoolbox` |
| Метаданные | `yt-dlp -J` → `MediaInfo` / `RawFormat` (Codable, все поля необязательные) |
| Выбор форматов | `OptionBuilder.build(from:canMerge:)` — чистая функция: H.264 в MP4 по высотам, стереозвук вместо 5.1, VP9/AV1 только если заметно легче, запасная цепочка в селекторе |
| Обложки | `MediaInfo.bestThumbnail` (по `preference`, JPEG важнее WebP), `ThumbnailService.saveJPEG` |
| Прогресс | Собственный `--progress-template` → `YtDlpOutput.parseProgress` → `DownloadProgress` (байты, всего, скорость, ETA). Этапы видео/аудио/склейка — `PhaseTracker` |
| Отмена | `MediaService.cancel()` → `SIGTERM` процессу yt-dlp |
| Повторы | На уровне yt-dlp: `--retries 5 --fragment-retries 10` |
| Ошибки | `YtDlpOutput.humanError` переводит вывод yt-dlp в русский текст с учётом площадки, VPN, cookies, ffmpeg, JS; `looksLikeEngineBreakage` отделяет «устарел движок» от «нет доступа» |
| Cookies | `--cookies-from-browser` из настроек (`NetworkOptions`), плюс свой прокси |
| Обновление yt-dlp | `EngineUpdater`: только после сбоя, похожего на устаревший движок, не чаще раза в 6 часов; ставит в Application Support |
| Настройки | `AppSettings` поверх UserDefaults |
| Журнал | `NSLog` в двух местах, структурного журнала нет |

## Можно ли использовать движок как бэкенд для iPhone

**Да, без переписывания.** `MediaService`, `OptionBuilder`, `Toolchain`,
`YtDlpOutput` не зависят от интерфейса и главного потока: `MediaService`
потокобезопасен (`@unchecked Sendable` с замком), остальное — чистые функции.
Всё это уже вызывается без интерфейса из `CommandLineCheck`.

Чего не хватает для бэкенда — это не переделка, а надстройка:

1. **Нормализация форматов для iPhone.** `OptionBuilder` ориентирован на Mac
   и прячет 1440p/2160p среди «экономных кодеков». AVPlayer не играет VP9,
   а AV1 — только на A17 Pro и новее, поэтому для iPhone нужен свой слой поверх
   того же `OptionBuilder`: до 1080p — H.264 с копированием потоков, выше —
   перекодирование в HEVC на Mac аппаратным `hevc_videotoolbox`.
2. **Задания.** Сейчас одна загрузка на модель интерфейса. Нужна очередь
   с ограничением одновременных загрузок, статусами и хранением результатов.
3. **HTTP-слой** с авторизацией, Range-запросами и потоковой отдачей файлов.
4. **Выбор обложки с запасом.** Найденный аудитом дефект: для старых роликов
   YouTube отдаёт 404 на `maxresdefault.jpg`, а следующий вариант не пробуется.
   На Mac это не роняло загрузку, но библиотеке на iPhone обложка нужна всегда.

## Решения, в которых я отступаю от промпта

**Сервер на Swift, а не FastAPI.** Промпт сам это допускает: проект не на
Python. HTTP-сервер — на Network.framework (`NWListener`): ноль зависимостей,
встроен в macOS и — главное — **сам умеет публиковать Bonjour-сервис**,
то есть обнаружение в сети получается бесплатно.

**Прямое скачивание на iPhone отклонено.** Проверено на живых ссылках YouTube:

| Свойство ссылки | Значение | Чем мешает |
|---|---|---|
| Параметр `ip=` | адрес Mac | с мобильной сети iPhone получит 403; при переносе бэкенда на VPS сломается всё и сразу |
| `expire` | 6 часов | задания в очереди и повторы рискуют протухнуть |
| Заголовки | User-Agent, Sec-Fetch-Mode и др. | нужно воспроизводить клиент yt-dlp |
| Дорожки | видео и звук раздельно | склейку пришлось бы переносить на телефон |
| JS-задача (`n`) | решает Deno на Mac | на iPhone её не решить |

Дома в одной Wi-Fi-сети адрес совпал бы — но это совпадение, а не гарантия,
и первое же переключение на мобильную сеть, VPN на Mac или переезд на VPS
ломает схему. Промпт требует, чтобы переезд на VPS не трогал iOS-приложение, —
значит, файл отдаёт бэкенд.

**Обнаружение и доступ: код сопряжения вместо ввода токена руками.**
Токен остаётся (Bearer, 32 случайных байта), но вводить 43 символа на телефоне
никто не будет. Mac показывает шестизначный код на 5 минут, iPhone обменивает
его на токен через `POST /api/v1/pair` и кладёт в Keychain.

**Задания хранятся в JSON, не в SQLite.** Состояние небольшое, а готовые файлы
и так лежат на диске. После перезапуска бэкенда незавершённые задания
помечаются как прерванные — iPhone видит понятный статус, а не вечные 63 %.

## Фоновая работа на iPhone — где честная граница

- Скачивание **на Mac** от iPhone не зависит: телефон можно заблокировать.
- Перенос **готового файла** на iPhone идёт фоновой `URLSession`
  с докачкой по Range и `ETag` — переживает блокировку и обрыв сети.
- Если телефон заблокировали, пока Mac ещё качает, приложение заранее ставит
  фоновый запрос `GET /jobs/{id}/file?wait=1`: сервер держит его до готовности
  файла и сразу отдаёт. Без push-уведомлений (для них нужна платная учётка
  Apple) это единственный способ продолжить без открытия приложения.

## Что потребует физического iPhone

Сборка и проверка идут в симуляторе. Share-расширение из приложения YouTube,
блокировка экрана, AirPlay и картинка в картинке проверяются только на
устройстве: для него в Xcode нужно выбрать свою команду разработчика
(подойдёт и бесплатный Apple ID — сборка тогда живёт 7 дней).
